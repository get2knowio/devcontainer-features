# Quickstart: Agentsh DevContainer Feature

## Consumer Usage

Add the feature to a project `.devcontainer/devcontainer.json`:

```jsonc
{
  "name": "my-project",
  "image": "mcr.microsoft.com/devcontainers/base:ubuntu",
  "features": {
    "ghcr.io/get2knowio/devcontainer-features/agentsh:0.1.0": {}
  }
}
```

Rebuild the devcontainer. On start, agentsh should be installed, the active policy should be
generated under `/run/agentsh/policy.yaml`, and the agentsh server should be running.

Verify inside the container:

```bash
agentsh --version
agentsh detect
cat ~/.ssh/id_rsa
env
curl https://example.com
```

Expected behavior:

- `agentsh --version` reports the pinned release.
- `agentsh detect` reports Landlock-level or stronger enforcement.
- Sensitive file read and bulk env dump are denied by policy.
- Unknown network access creates a pending approval, served over the agentsh REST API.

## Custom Overlay

Create `.devcontainer/agentsh-policy.yaml` in the project workspace to replace the default
project policy while keeping the security floor:

```yaml
file_rules:
  - name: allow-workspace
    paths: ["/workspace/**", "/workspaces/**"]
    operations: [read, write, create]
    decision: allow

network_rules:
  - name: allow-example
    domains: ["example.com"]
    ports: [443]
    decision: allow

  - name: deny-other-network
    decision: deny
```

Restart the container. The startup log should show `source=overlay:<path>`.

## Developer Validation

From the repository root:

```bash
shellcheck src/agentsh/install.sh src/agentsh/scripts/start-server.sh
devcontainer features test --features agentsh --base-image mcr.microsoft.com/devcontainers/base:ubuntu .
devcontainer features test --features agentsh --base-image mcr.microsoft.com/devcontainers/base:debian .
devcontainer features test --features agentsh --base-image alpine:3.19 .
devcontainer features test --features agentsh --skip-autogenerated .
```

Release validation must also cover `amd64` and `arm64` before publishing.

## Approvals

Policy rules with `decision: approve` create pending approvals that agentsh serves over its
REST API. With no notifier attached they time out and deny after `approvalTimeoutSeconds`
(the secure default). To resolve them interactively, attach a notifier sidecar that polls the
authenticated `/api/v1/approvals` endpoint (see below).

## External Notifier Sidecar

When a separate notifier container polls agentsh directly, enable the generic REST sidecar
options:

```jsonc
{
  "features": {
    "ghcr.io/get2knowio/devcontainer-features/agentsh:0.1.0": {
      "externalRestApi": true,
      "restApiKey": "replace-with-a-generated-secret"
    }
  }
}
```

The consuming project must place the devcontainer and notifier on a shared Docker or Compose
network. Dev Container Features do not create dedicated Docker networks.

## Failure Modes

- If the overlay is malformed, startup fails.
- If the security floor is missing or malformed, startup fails.
- If enforcement falls below Landlock-level, build or startup fails.
- If no approver resolves a pending approval, approval-required actions fail secure after timeout.
