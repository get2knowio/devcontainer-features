# Contract: Validation and Release Tests

## Pull Request Validation

Required checks for changes touching `src/agentsh/**`, `test/agentsh/**`, policy docs, or
release workflows:

1. Shellcheck `src/agentsh/install.sh`, `src/agentsh/install-main.sh`, `src/agentsh/scripts/start-server.sh`, and the `test/agentsh/integration/*.sh` probes.
2. `devcontainer features test --features agentsh --skip-autogenerated .` for the shims-off scenarios. agentsh is intentionally excluded from the autogenerated/default matrix because its default replaces `/bin/sh`, which the harness uses to bootstrap containers.
3. Docker integration probes (outside the harness, on a Landlock-capable kernel): `shim_integration_test.sh` (real `/bin/sh`+`/bin/bash` mediation via `/bin/sh.real`), `overlay_test.sh` (overlay selection + self-protection floor), and `rest_auth_test.sh` (external REST API key auth on `/api/v1/*`).
4. Policy merge validation for default, overlay, malformed overlay, and missing floor cases.

## Scenario Matrix

Harness scenarios run with `installShellShims=false` (so the harness can boot). Shell-shim
mediation and overlay-at-startup are validated by Docker integration probes instead, because
the harness mediates `/bin/sh` for bootstrap and does not expose the workspace mount to the
feature entrypoint.

| Scenario / probe | Where | Required Assertions |
|------------------|-------|---------------------|
| default | harness | agentsh installed; default policy + `/etc/agentsh/config.yaml` installed; REST private + unauthenticated by default; runtime policy generated; shim binary installed; shells not replaced (installShellShims=false); at least Landlock-level enforcement; sensitive reads denied; env dump denied; agentsh-native approval fallback present |
| external-rest-api | harness | `config.yaml` binds `0.0.0.0`; api_key auth enabled; `api_keys.yaml` is a root-level `{name,key}` list (read via sudo) |
| approval-timeout | harness | approvals enabled in `config.yaml`; `approvals.timeout` reflects `approvalTimeoutSeconds` |
| malformed-overlay | harness | merge of a malformed overlay fails clearly |
| missing-floor | harness | merge with a missing floor fails clearly |
| ubuntu / debian / alpine | harness | install/config artifacts present across glibc and musl base images |
| shim_integration_test | docker | `/bin/sh` and `/bin/bash` mediated (`state=installed`, `shim_matches=true`); `/bin/sh.real`/`/bin/bash.real` preserved; `shim.conf` has `force=true` |
| overlay_test | docker | overlay selected and logged; overlay replaces default network behavior; security floor remains prepended (self-protection) |
| rest_auth_test | docker | `/api/v1/*` returns 401 without key, 200 with the configured key, 401 with a wrong key |

## Base Images

Validation must cover:

- Ubuntu 22.04 or newer devcontainer base
- Debian 12 devcontainer base
- Alpine 3.19 or newer base

## Architectures

Release validation must cover:

- `amd64`
- `arm64`

If GitHub-hosted runner availability prevents native coverage, the workflow must use a
documented emulation/buildx strategy or block release until coverage is available.

## Release Validation

Release publish is blocked unless:

- PR validation passes.
- Feature metadata version is correct.
- Documentation generated from metadata matches checked-in docs.
- `ghcr.io/get2knowio/devcontainer-features/agentsh:<version>` and `:latest` publish from
  the release workflow.
- GHCR visibility is public or documented as a required manual post-publish action.
